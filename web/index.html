Milestone 2 · Communication prototype/comm on GitHub

Milestone 2 replaces the simple messages above with a real communication layer: TCP sockets, every message a JSON envelope (type, msg_id, sender, timestamp, reply_to, payload) sent as a 4-byte length header + UTF-8 body, and three patterns: request-reply (client ↔ lot server), publish-subscribe (sensors → broker → subscribers) and group communication (lot servers join a group at the registry and fan summaries out to every member). Two new processes: the broker (:5000) and the registry (:5010). Every process logs every message it sends or receives; a crashed lot server replays its log. Each diagram below has a download button so it can go straight into the report.

Communication model

Who connects to whom. Every arrow is a TCP connection carrying framed JSON. A lot server is a service to clients, a subscriber and publisher at the broker, and a member of the lot_servers group.

sensor node (publisher) broker (pub-sub) lot server (service, subscriber, publisher, group member) registry (group membership) client (request-reply, subscriber)

Request-reply

One connection per exchange: open, REQUEST, REPLY, close. The REPLY echoes the REQUEST's msg_id in reply_to. No reply within 2 s → the client reconnects and resends the same REQUEST; the service caches replies by msg_id, so the retry gets the cached answer and the reservation is never made twice.

Publish-subscribe

Subscribers keep one long-lived connection to the broker. A PUBLISH is fanned out as one EVENT per subscriber on that subscriber's own connection, one log line per delivery. The publisher gets an ACK with how many subscribers were reached. A subscriber the broker cannot deliver to is dropped from the topic.

Group communication

Members JOIN a group at the registry. To send, the sender asks the registry for MEMBERS, then opens one connection per member and sends GROUP_MSG. An unreachable member is logged and skipped; the others still get the message. No ordering or atomic delivery is guaranteed.

Message envelope

Every message, in every pattern, is a JSON object with these fields, sent as a 4-byte big-endian length followed by the UTF-8 body.

fieldmeaning
typeREQUEST, REPLY, SUBSCRIBE, UNSUBSCRIBE, PUBLISH, EVENT, ACK, JOIN, LEAVE, MEMBERS, GROUP_MSG — used to dispatch
msg_idunique id; a REPLY or ACK carries the id it answers in reply_to
senderprocess name, for the logs
timestampISO 8601 with milliseconds, sender's clock
payloadtype-specific data
